# Phase 9 — Post-implementation audit fixes

**Objective:** Phases 0–8 were implemented and mostly hold up under direct code inspection — but a repo audit turned up six specific issues: some fixes that are cosmetically present but not actually enforcing anything, and one genuinely new false claim introduced while fixing the old ones. Fix these without breaking what Phases 0–8 already got right.

Task hints:
- **CI's lint check is fake-green.** `.github/workflows/ci.yml` runs `ruff check --exit-zero semanticfs/` — `--exit-zero` forces the step to report success regardless of how many violations exist, so it's decorative, not enforcing anything. Remove `--exit-zero` (let ruff fail the build on real violations, fixing whatever it flags first), and add a real `mypy semanticfs/` step — `mypy` is already declared in the `dev` extra but never actually runs in CI.
- **CI doesn't run the full test suite.** The `pytest` step only runs `tests/test_ast_chunker.py tests/test_query_parser.py tests/test_store_scoring.py` — the pre-existing tests (`test_context.py`, `test_embedder.py`, `test_linker.py`, `test_store.py`) never execute in CI. Change the step to `pytest tests/` (or explicitly list every test file) so the green checkmark actually means the whole suite passed. If any of the older tests fail once actually run, fix them rather than quietly excluding them again.
- **Remove the new "Linux/macOS (Supported)" claim from the README's System Requirements table, or make it true.** `os.startfile()` and a hardcoded `explorer.exe` subprocess call are still present in `cli.py`, and `context.py` imports `pygetwindow` (Windows-oriented) directly — there is zero `platform.system()`/`sys.platform` branching anywhere in the codebase. Either (a) change the table back to "Windows (Primary/only supported today)" and remove the Linux/macOS claim, or (b) if cross-platform support is actually wanted, add real OS branching for the file-reveal action (e.g. `subprocess.run(["open", filepath])` on macOS, `xdg-open` on Linux) and only then claim support. Don't leave the claim in place unless (b) is actually done.
- **Declare `pygetwindow` as a real dependency.** It's imported in `context.py` but appears nowhere in `pyproject.toml` — add it to the base `dependencies` list (or gate the import behind a `try/except` with a clear degraded-mode message if the active-window-context feature should be optional).
- **Fix the benchmark eval set size and reconcile the latency numbers.** `benchmarks/eval_set.json` has 10 queries against 5 fixture files — expand this to at least 30–50 query/fixture pairs across more categories so "100% Top-1 accuracy" isn't a fragile number from a tiny sample (a single miss on a 10-item set swings the headline number by 10 points). Separately: `run_benchmarks.py`'s p95/p99 logic only produces real percentiles at n≥20/n≥100 — with the current 10-query set they silently collapse to just the max value. Once the eval set is expanded, confirm the README's quoted p50/p95/p99 figures (14.8/22.1/31.4ms) are actually regenerated by this script — if they still come from an old internal stress run, either regenerate them from the real reproducible script or label them clearly as a separate, larger-scale internal measurement.
- **Actually add the demo.** Phase 8's commit added descriptive text about the "live monokai preview" but no embedded visual. Record a real terminal session (`asciinema` or a `.gif` via `vhs`) showing `sfind <query>` with the interactive menu working, and embed it near the top of the README, above the feature list.

**Acceptance criteria:**
- `ruff check` (no `--exit-zero`) and `mypy` both run in CI and must pass for the build to be green.
- `pytest` in CI runs every test file in `tests/`, not a subset.
- The README's OS support claim matches what the code actually does — no unverified "Supported" claims.
- `pygetwindow` installs correctly via a plain `pip install -e .`.
- Benchmark eval set has enough queries that p95/p99 are real percentiles, not the max-value fallback, and the headline accuracy number isn't swingable by a single query.
- README has an actual embedded demo recording, not just descriptive text about the feature.

**Context for the agent:** these are things that were claimed fixed in the Phase 0–8 commits but verification found gaps between the claim and the code. Fix root causes, not just whatever makes a specific check pass — e.g. don't silence a linter to make CI green, actually fix what it flags.
